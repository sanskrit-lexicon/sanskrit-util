# Episteme registry protocol — confirm → promote → delete

_Created: 08-07-2026 · Last updated: 08-07-2026_

The seven episteme registries (`ASSUMPTIONS`, `CONTRADICTIONS`, `GAPS`, `DEAD_ENDS`, `RECIPES`,
`STALENESS`, `GLOSSARY`) are **staging areas**, not archives. A row is a claim in one of a few
states; a human moves it along until it either becomes a settled `FINDINGS`/decision fact or is
deleted. This file is the exact algorithm for that. Rows carry two markers that drive it:

- **Origin:** `⚙️ auto` (a seed script emitted it — an *unconfirmed candidate*) · `✍️ human` (a
  session vouched for it).
- **Importance dot:** 🔴 3 · 🟠 2 · 🟡 1 (the same scale as FINDINGS; what it *rates* varies by
  layer — blast radius, impact, value-if-measured, re-attempt cost).

---

## State machine

```
                ┌─────────────┐   confirm (evidence checked)   ┌─────────────┐
  seed script → │  ⚙️ auto     │ ─────────────────────────────► │  ✍️ human    │
                │ (candidate) │                                │ (vouched)   │
                └──────┬──────┘   reject (not real / dup)      └──────┬──────┘
                       │  └───────────────► delete (with 1-line reason in the commit)
                       │                                              │
                       │                    graduate (see per-layer rule)
                       ▼                                              ▼
                    delete                             FINDINGS row  /  CROSS_REPO_DECISIONS D##
```

`STALENESS` is exempt — it is fully regenerated by `derive_staleness.py`; never hand-edit it.
`GLOSSARY` and `RECIPES` are **living** (see below): they are maintained, not graduated-away.

---

## Algorithm 1 — confirm or reject an `⚙️ auto` candidate

Run this whenever a seed script (`seed_gaps.py`, `seed_dead_ends.py`, `seed_recipes.py`,
`seed_contradictions.py`, `scan_assumptions.py`) has added `⚙️ auto` rows.

1. **Read the `> **Source:**` line** and open what it cites (the manifest row, the FINDINGS §,
   the QUESTIONS_LOG id, the crosswalk file). An auto row is only a *pointer* — it has not been
   read by a human yet.
2. **Decide real-or-not:**
   - **Not real / duplicate / already covered by an existing row** → **delete** the row; state
     why in the commit message (e.g. "dup of §3", "already in FINDINGS §12"). Do not leave dead
     `⚙️` rows lying around — an unconfirmed candidate that is wrong is noise.
   - **Real** → continue.
3. **Fill the blanks the script left** (`<why it matters>`, `<how to close>`, `Test to confirm`,
   the failure mode, etc.) from the source you just read. Never leave a `<placeholder>` in a
   confirmed row.
4. **Flip `⚙️ auto` → `✍️ human`** and set the importance dot deliberately (the script guesses
   🟡; you decide the true blast-radius / value / cost).
5. Commit. The row is now a vouched claim, eligible for graduation.

> An `⚙️` row is a *candidate until a human confirms* — it is never cited as settled fact and
> never counted as "done". The dashboard's ⚙️-vs-✍️ split is exactly this backlog.

## Algorithm 2 — graduate a `✍️ human` row (per layer)

A row graduates the moment its own exit condition is met. Each layer has one:

| Layer | Exit condition | Graduates to | Leave behind |
|-------|----------------|--------------|--------------|
| **ASSUMPTIONS** | its `Test to confirm` **passes on the full data** (not a sample) | a `FINDINGS` row stating the now-measured fact | nothing — delete the assumption |
| **GAPS** | the quantity is **measured** | a `FINDINGS` row with the number | nothing — delete the gap |
| **CONTRADICTIONS** | a human **rules** which position wins (or that both stand) | a `CROSS_REPO_DECISIONS` `D##` | a one-line tombstone `→ D##, resolved DD-MM-YYYY` |
| **DEAD_ENDS** | *(does not graduate)* — a negative result is permanent | — | it stays; revisit only if its `Don't retry unless` condition becomes true, then it may spawn a fresh attempt |
| **RECIPES** | *(living)* — a reproduction recipe is maintained, not retired | — | update it when the command/inputs change |
| **GLOSSARY** | *(living)* — terminology is maintained | — | update `Means/Not/Canonical/Examples` as usage settles |
| **STALENESS** | *(auto)* — never hand-touched | — | regenerate with `derive_staleness.py` |

**Graduation steps (ASSUMPTIONS / GAPS → FINDINGS):**

1. Do the measurement / run the `Test`. Record the number.
2. Append a `FINDINGS` row (next free `§N`, its own importance dot, an `Evidence:` line with the
   number + file, an `Implication:`, and a `> Source`). FINDINGS is measured-fact-only — this is
   where the settled result belongs.
3. **Delete** the episteme row (it has served its purpose). If other episteme rows linked to it
   via `↔ Interlinks`, repoint them at the new FINDINGS §.
4. `STALENESS` will pick the new FINDINGS row up on its next regeneration automatically.

**Graduation steps (CONTRADICTIONS → decision):**

1. A human rules (via `/decision-record` or directly). Append a `CROSS_REPO_DECISIONS` `D##`
   with the rationale.
2. Replace the contradiction's `Status:` line with `✅ → D##, resolved DD-MM-YYYY` and keep the
   row as a **one-line tombstone** (so the disagreement's history isn't lost), or delete it and
   cite `D##` — either is fine; a tombstone is preferred for contested calls.

## Algorithm 3 — when to just delete

Delete (don't graduate) when a row is: a duplicate, superseded by a later measurement, based on
a premise that itself got deleted, or simply wrong. Always give a one-line reason in the commit.
Deleting is the healthy default for stale `⚙️` candidates — the registries are only useful if
they stay live.

## Provenance conventions (every `> **Source:**` line)

Enforced by [`_provenance.py`](_provenance.py) + [`normalize_provenance.py`](normalize_provenance.py)
(run the normalizer as the finishing pass before committing edited registries):

- **Every repo tag is a clickable link** (verified owner map in `_provenance.py`) — no bare
  `kosha/csl-guides`.
- **The model tag is the bare version id** in backticks: `` `claude-opus-4-8` ``, not
  "Opus 4.8 (`claude-opus-4-8`)" — the version alone is enough in these compact lines. (This is
  a deliberate local relaxation of the global "tier AND version" rule, which still governs run
  logs, handoffs, and paper methods sections.)
- **The date links** to that day's commits in the registry's own repo, so a reader can see what
  landed when.
